# MANDATE — Requirements Registry

The design vision lives in [DESIGN.md](./DESIGN.md). This file decomposes it into
small, addressable requirements with stable IDs. Tests reference these IDs in
comments (e.g. `// SPEC-CRED-1`), and `npm run spec:trace` fails CI if any
requirement tagged `[testable]` has no referencing test.

Tag meanings: `[testable]` = must be covered by an automated test;
`[design]` = narrative/UX intent, verified by review rather than tests.

## Simulation core
- **SPEC-SIM-1** `[testable]` The simulation is deterministic: same seed + inputs reproduce a run exactly. Engine code never calls `Math.random()` or reads the wall clock.
- **SPEC-SIM-2** `[design]` The full financial network is the single source of truth; all dashboards and the fractal-zoom map are read-only views derived from it.
- **SPEC-SIM-3** `[testable]` A pure `tick(state, months)` advances `state.date` by N months on the `YYYY-MM` calendar and maintains a bounded `state.history: GameStateSnapshot[]` (size from `content/engine/params.json#tick.history_size`). By convention `state.history` excludes the current state; `history[0]` is the most-recent prior snapshot (`date − 1 month` after a 1-month tick). The function returns a new `GameState` and does not mutate the input.
- **SPEC-SIM-6** `[testable]` The simulation tick cadence is parameterised via `content/engine/clock-cadence.json` (`schemas/clock-cadence.schema.json`). `ticks_per_month` controls how many dynamics steps run per calendar month. `scaleParamsForTick(params, n)` in `src/engine/cadence.ts` re-expresses monthly `MacroDynamicsParams` as per-tick params: `inflation_persistence` uses power scaling (`p^(1/n)`), `unemployment_adjustment_speed` uses exact discrete-time scaling (`1−(1−α)^(1/n)`), and flow contributions (`phillips_slope`, `expectations_adaptivity`, `expectations_anchor_pull`, `credibility_mission_gain`) are divided by n. `Session.advance()` uses the cadence to run `ticks_per_month` sub-tick dynamics steps per calendar month; the FOMC meeting schedule remains month-based; `months_below_anchor` increments by at most 1 per calendar month regardless of cadence. Documented tolerance: monthly and weekly (n=4) trajectories agree within 0.2pp (20 bp) for `inflation`, `unemployment`, and `expectations_anchor` over 36 months.
- **SPEC-SIM-4** `[testable]` A **replay** is a schema-governed content artifact under `content/replays/` capturing the **player's strategy** — a structured sequence of `{date, policy_rate, ...}` actions, with no engine-computed values. The engine-side runner `runReplay(replayId, months)` in `src/engine/replay.ts` applies the strategy to the engine via `tick` and returns an **in-memory** trajectory (not committed; engine-computed values stay in memory). Two consecutive `runReplay` calls produce bit-identical trajectories. Replay actions with dates outside the simulated `[0, months)` window are surfaced via `UnconsumedReplayActionsError` so author typos don't silently produce mis-aligned trajectories. At least one committed replay (`content/replays/1979_chair_tightening.json`, id `replay.1979_chair_tightening`) is loadable via `loadReplay`.

## Credibility & expectations
*`SPEC-CRED-1`/`SPEC-CRED-4` were redesigned (issue #33 + the realistic-dynamics calibration): dissent no longer costs credibility, credibility is tied to the mandate mission (`SPEC-CRED-6`), and the binary de-anchoring spiral became a continuous credibility-weighted expectations model.*

- **SPEC-CRED-1** `[testable]` Market surprises reduce credibility and on-target outcomes raise it; the value is clamped to [0, 100]. Committee **dissents do not change credibility** — FOMC dissents are not published in a way that damages the Chair's standing, so `applyMeetingOutcome` ignores the dissent count for credibility purposes; consensus-building costs are modelled separately (issue #33).
- **SPEC-CRED-2** `[testable]` Inflation expectations remain anchored only at or above a credibility threshold.
- **SPEC-CRED-3** `[testable]` Lower credibility increases the "pain multiplier" on policy moves (1x at full credibility up to 3x at zero).
- **SPEC-CRED-4** `[testable]` Within `applyMacroDynamics`, inflation **expectations** (`expectations_anchor`) evolve continuously each month, weighted by credibility (replacing the slice-1 binary spiral). With `c = credibility / 100`: `expectations_anchor += expectations_adaptivity * (1 - c) * (inflation - expectations_anchor) - expectations_anchor_pull * c * (expectations_anchor - target_inflation)`. When credibility is low, expectations track recent realized inflation (adaptive — they de-anchor in whatever direction inflation is moving); when credibility is high, they are pulled toward `target_inflation` (re-anchoring), which historically delivered roughly half the disinflation. `state.vars.months_below_anchor` still increments each month that `credibility < anchor_threshold` and is **frozen, not reset** on recovery, preserving the persistent-memory stat surfaced by the UI. Params (`expectations_adaptivity`, `expectations_anchor_pull`, `target_inflation`, `anchor_threshold`) live in `content/engine/credibility.json` (schema-governed).
- **SPEC-CRED-6** `[testable]` Credibility is tied to the **mandate mission**, not committee voting. Within `applyMacroDynamics`, define the dual-mandate distance `D = |inflation - target_inflation| + credibility_unemployment_weight * |unemployment - unemployment_target|`. Credibility changes by `credibility_mission_gain * (D_before - D_after)` for the month's move (using the pre- and post-update inflation/unemployment) and is clamped to [0, 100]: it **rises when the economy moves toward target and falls when it moves away**. `credibility_unemployment_weight < 1` makes disinflation progress dominate, so winning the inflation fight builds credibility even through a policy-induced recession. Params (`credibility_mission_gain`, `credibility_unemployment_weight`, `unemployment_target`, `target_inflation`) live in `content/engine/credibility.json` (schema-governed). Implements issue #33.

## Data fog
- **SPEC-FOG-1** `[testable]` A pure `observe(state, seriesId, rng)` returns a fogged view of the true state variable, with `noise_scale` and `lag_months` parameters from `content/engine/params.json#fog[seriesId]` (validated by `schemas/engine-params.schema.json`). Lag indexing: `lag_months === 0` reads the current `state.vars[seriesId]`; `lag_months >= 1` reads `state.history[lag_months - 1].vars[seriesId]`; out-of-range falls back to the current value. Same seed + state → same observation.

## Committee
*`SPEC-COMM-1`/`SPEC-COMM-2` defined the original committee model; `SPEC-COMM-3` redesigned it around empirical FOMC dynamics after player feedback that the trichotomy produced 1500bp dot spreads instead of the historical ~150bp.*

- **SPEC-COMM-1** `[testable]` A committee schema (`schemas/committee.schema.json`) and content (`content/committees/1979.json`) define members with stable loc-key names and per-member coefficient fields. `name` is constrained to localization-key shape `^[a-z][a-z0-9_.]+$`. `npm run validate` accepts `content/committees/1979.json`. No engine changes in this SPEC.
- **SPEC-COMM-2** `[testable]` A pure `vote(committee, proposedRate, state, params): { decided, dissents }` simulates an FOMC vote and counts members where `|preferred - proposedRate| > member.compromise_band` (threshold is per-member — see SPEC-COMM-4). `decided` is `proposedRate` for slice 1 (the committee has no override power yet). `params` is required — callers resolve via `loadCommitteeParams()`. Missing or non-finite `state.vars.inflation`, `state.vars.unemployment`, or `state.vars.policy_rate` throws `VoteMissingVarError`; non-finite `proposedRate` throws a plain `Error` (caller bug, not a content authoring error). No silent default-to-zero in any path. The dissent count is surfaced in the `FomcVote` and the committee briefing UI, but per issue #33 (SPEC-CRED-1) dissents no longer feed `applyMeetingOutcome` / credibility.
- **SPEC-COMM-3** `[testable]` Per-member preferred rate is a Taylor-rule reaction function with **continuous per-member coefficients** (`inflation_coef`, `output_coef`, `inertia`), anchored at the committee-wide `neutral_rate` and smoothed against the lagged policy rate. The formula is `inertia * laggedRate + (1 - inertia) * (neutral_rate + inflation_coef * (inflation - target_inflation) - output_coef * (unemployment - target_unemployment))`. The 1979 committee has **12 voting members** (7 governors + NY Fed permanent + 4 rotating regional presidents), matching the historical FOMC. Empirical anchors live in `docs/research/2026-06-02-fomc-empirical-anchors.md`. The dropped `hawkish_inflation_weight` / `dovish_unemployment_weight` / `neutral_blend` / per-member `lean` enum are removed entirely; an additional `previewVote` helper returns the per-member preferred rates a UI needs to surface the briefing.
- **SPEC-COMM-4** `[testable]` Each committee member carries their own `compromise_band` (the range around their preferred rate they will assent to); `vote()` and `previewVote()` judge dissent per-member using that band. The global `dissent_tolerance` field is removed from `CommitteeParams`. Given two members with different band widths, a proposal at a distance inside the wide-band member's tolerance but outside the narrow-band member's produces exactly one dissent. Given all members have the same band width equal to the old global default, behavior is unchanged.
- **SPEC-COMM-5** `[testable]` A trait system for committee members: a continuous `conviction` dial per member (in [0, 1]) that narrows the effective compromise band (`effective_band = compromise_band * (1 - conviction * conviction_band_factor)`, where `conviction_band_factor` is schema-governed in `content/engine/committee.json`); plus a named, content-defined trait catalog (`schemas/traits.schema.json`, `content/traits/`) whose entries declare always-on effects (`preferred_rate_shift`, `band_modifier`) and signal-reactive hooks (dormant until the referenced series exists). Given a high-conviction member, their effective band is narrower than a low-conviction member with the same `compromise_band`. Given a member tagged with a hawkish-lean trait, their preferred rate shifts up by the trait's declared amount. `npm run validate` accepts a well-formed trait catalog and rejects one missing a required field.
- **SPEC-COMM-6** `[testable]` Between FOMC meetings each member's preferred-rate (stance) drifts toward their Taylor-rule prescription from incoming macro data. A pure `applyIntermeetingDrift(state, committee, params): GameState` evolves each member's stance one month: `new_stance = inertia * prev_stance + (1 - inertia) * taylor_target`, where `taylor_target = neutral_rate + inflation_coef * gapInflation - output_coef * gapUnemployment`. The previous stance is read from `state.vars["stance.<memberId>"]`; on first call (key absent) it falls back to `state.vars.policy_rate`. Stances are written back to `state.vars["stance.<memberId>"]`. `previewVote` uses the stored stance as the lagged-rate anchor if present, so meeting stances reflect the intermeeting period rather than recomputing cold from `policy_rate`. `applyIntermeetingDrift` is called each month in `Session.advance()`. Given two members identical except for `inflation_coef`, a one-month drift with rising inflation moves the higher-`inflation_coef` member's stance more. Given a state near steady state, drift produces negligible change. Pure: no `Math.random` / `Date.now` (SPEC-SIM-1).

## Engine session
- **SPEC-SESSION-0** `[testable]` A pure Session façade wraps tick + vote + applyMeetingOutcome with identity-stable getters and a subscribe protocol consumed by useSyncExternalStore in the future web UI. Skeleton in slice 2; the successor spec fully wires the macro dynamics. `Session.fromScenario(scenarioId, seed, committeeId)` and `Session.fromReplay(replayId, seed, committeeId)` are the two static factories; `committeeId` identifies the FOMC committee content file used by `proposeRate`. `advance(months)`, `proposeRate(rate)`, `reset()`, and `setForwardGuidanceStance(stance)` are the mutators. `get current(): GameStateSnapshot` and `get trajectory(): readonly GameStateSnapshot[]` return referentially-stable values that change reference only on mutation. `subscribe(listener)` returns an unsubscribe function; listeners fire synchronously after each mutation but never on getter reads.
- **SPEC-SESSION-1** `[testable]` `Session.proposeRate()` is gated to scheduled FOMC meeting months defined in `content/engine/meeting-schedule.json` (schema-governed). `Session.isMeetingMonth(date?: string): boolean` returns true iff the given date's month falls in the schedule. Calling `proposeRate()` outside a meeting month throws `NotMeetingMonthError` (with `public readonly date: string`).
- **SPEC-GUIDE-2** `[testable]` Proposing a rate inconsistent with the active forward-guidance stance surprises markets and costs credibility. A pure `marketsSurprised(stance, currentRate, decidedRate, tolerance): boolean` returns true when the decided rate's move contradicts the guided direction: a **hawkish** stance is surprised by an easing (`decided - current < -tolerance`), a **dovish** stance by a tightening (`decided - current > tolerance`), and a **neutral** stance by any move beyond the band (`|decided - current| > tolerance`); a move within `tolerance` of the current rate never surprises. `Session.proposeRate` computes this from the stored stance and the pre-meeting policy rate and feeds it to `applyMeetingOutcome`, activating the SPEC-CRED-1 `-5` surprise lever that was previously pinned `false`. `surprise_tolerance` lives in `content/engine/guidance.json` (schema-governed).
- **SPEC-GUIDE-1** `[testable]` `Session.setForwardGuidanceStance(stance)` scales the expectations re-anchoring pull. Inside `Session.advance()`, the `expectations_anchor_pull` passed to `applyMacroDynamics` is multiplied by `stance_multiplier` — `hawkish_multiplier`, `neutral_multiplier`, or `dovish_multiplier` from `content/engine/guidance.json` (schema-governed) — so hawkish guidance re-anchors expectations toward `target_inflation` faster and dovish slower. The stance is stored on the Session, not in `state.vars`.

## Calibration
- **SPEC-CAL-1** `[testable]` Real FRED data for 1979-08 through 1986-12 is committed as `content/calibration/fred_1979_1986.json` and a calibration harness `tools/calibrate.ts` runs the canned 1979 chair-tightening replay through the engine and emits a CSV comparing engine output to FRED. A `npm run calibrate` script produces the comparison. The harness now drives the full engine (`Session.advance` runs the real-rate dynamics) and reports policy_rate, inflation, and unemployment RMSE; the SPEC-CAL-1 test asserts the FRED data loads correctly and the harness runs deterministically, while the asserted convergence tolerances live in SPEC-CAL-2.
- **SPEC-CAL-2** `[testable]` Driving `Session.fromReplay("replay.1979_chair_tightening", …)` forward month-by-month across the full 1979-08…1986-12 window (so the real-rate dynamics, expectations, and mission-tied credibility all run) reproduces the FRED baseline within tolerance: the root-mean-square error of the engine trajectory vs FRED, aligned month-for-month, is `< 0.025` (2.5pp) on `inflation` and `< 0.020` (2.0pp) on `unemployment`. The disinflation arc is asserted directionally too (inflation ends well below its 1979 level; unemployment peaks in recession then partly recovers; credibility ends above its start). This pins the realistic-dynamics calibration so macro-model regressions surface as a failing test; two runs are identical (determinism). The 1979-80 inflation peak (second oil shock) is a supply shock left to content events, not the demand-side core, so the tolerance is deliberately loose.
- **SPEC-CAL-3** `[testable]` Calibration thresholds are content-governed, not hardcoded. A new content type `schemas/calibration-thresholds.schema.json` defines `CalibrationThresholds` (`inflation_rmse_max`, `unemployment_rmse_max`, `policy_rate_rmse_max` — all positive numbers). One committed instance: `content/engine/calibration-thresholds.json`. `tools/validate-content.ts` registers it. A `loadCalibrationThresholds()` function (with module-level cache) reads and validates the file. `tools/calibrate.ts` is extended to call `loadCalibrationThresholds()` and, after computing RMSE values, emit a `PASS`/`FAIL` verdict line for each metric to stderr (format: `inflation    RMSE: 0.0123 PASS (< 0.0250)`). The harness exits with code 0 even when a metric fails — this is a "soft gate" that warns without blocking. A test in `test/calibration-thresholds.test.ts` asserts: `loadCalibrationThresholds()` loads successfully and returns finite positive values; the schema rejects a file with a negative threshold.

## Macro dynamics
- **SPEC-LAG-1** `[testable]` A distributed-lag kernel translates the history of real-rate gaps into `state.vars.output_gap`. A pure `applyRateToOutputGap(state, trajectory, lagParams, realNeutralRate): GameState` reads up to N recent snapshots from `trajectory` (reverse-chronological order), computes `realGap[k] = (policy_rate[k] - expectations_anchor[k]) - realNeutralRate` for each, and returns a new state with `output_gap = Σ weights[k] * realGap[k]` where `weights` (from `content/engine/lags.json`) sum to 1 and follow an exponential decay with ~6-month half-life. `applyMacroDynamics` uses `state.vars.output_gap ?? realGap` for the Okun unemployment-equilibrium computation, so existing tests without `output_gap` are unaffected. Session.advance() calls `applyRateToOutputGap` before `applyMacroDynamics` each month.

- **SPEC-TERM-1** `[testable]` A `state.vars.long_rate` variable tracks the long end of the yield curve via exponential weighted moving average (EWMA) toward `policy_rate`. A pure `applyTermStructure(state, params): GameState` computes `λ = 1 - exp(-ln(2) / half_life_months)` from content, then `long_rate_new = (1 - λ) * long_rate + λ * policy_rate`; if `long_rate` is absent from state it defaults to `policy_rate` (cold-start). Returns a new state with `long_rate` updated; never mutates the input. Params (`half_life_months`) live in `content/engine/term-structure.json` (schema-governed). `Session.advance()` calls `applyTermStructure` each month after `applyMacroDynamics`. Tests assert: EWMA convergence (long_rate approaches policy_rate asymptotically), cold-start defaults to policy_rate, half_life_months=1 gives λ=0.5, purity, and Session.advance(12) produces a finite `long_rate` var.

- **SPEC-SIM-5** `[testable]` A pure `applyMacroDynamics(state, params): GameState` in `src/engine/dynamics.ts` evolves the macro state one month via a **real-rate transmission** model. All four var updates read the **prior** month's vars (a simultaneous update), so the step is order-independent and matches the calibration harness. Let `realRate = policy_rate - expectations_anchor` (the ex-ante real rate) and `realGap = realRate - real_neutral_rate`.
  - **Unemployment** mean-reverts toward a policy-implied equilibrium: `u_eq = unemployment_natural_rate + okun_coefficient * realGap`; then `unemployment += unemployment_adjustment_speed * (u_eq - unemployment)`. Tight policy (high real rate) raises equilibrium unemployment with a lag; returning to neutral lets unemployment recover — fixing the slice-1 model where a nominal-rate gap drove unemployment in one direction forever.
  - **Inflation** follows an expectations-augmented Phillips curve with momentum: `inflation = inflation_persistence * inflation + (1 - inflation_persistence) * expectations_anchor - phillips_slope * (unemployment - unemployment_natural_rate)`.

  Both are clamped (`inflation >= 0`, `unemployment` in `[0,1]`). The `expectations_anchor` (SPEC-CRED-4), `credibility` (SPEC-CRED-6), and `months_below_anchor` updates run inside this same simultaneous step. Macro params (`inflation_persistence`, `phillips_slope`, `unemployment_natural_rate`, `real_neutral_rate`, `okun_coefficient`, `unemployment_adjustment_speed`) live in `content/engine/dynamics.json`; expectations/credibility params live in `content/engine/credibility.json` (both schema-governed). `applyMacroDynamics` is called once per month inside `Session.advance()`; the slice-1 `applyMonthlySpiral` call is removed (its role is absorbed here). The model has a clean steady state at `inflation = expectations_anchor = target_inflation`, `unemployment = unemployment_natural_rate`, `policy_rate = target_inflation + real_neutral_rate` — a stable, winnable target.

## Briefings
- **SPEC-BRIEF-1** `[testable]` A briefing content type: `schemas/briefing.schema.json` + loader (`src/content/briefings.ts`) + at least one committed briefing in `content/briefings/`. Each briefing exposes exactly three policy-scenario branches in order — raise, hold, lower — each with a forecast payload (`inflation_outlook`, `unemployment_outlook`, optional `growth_outlook`). The schema enforces branch order via `prefixItems`; the loader additionally validates order at runtime and throws `BriefingScenarioOrderError` if violated. `loadBriefing(id)` throws `BriefingNotFoundError` for an unknown id. The `name`/`desc`/scenario `name` fields are constrained to localization-key shape `^[a-z][a-z0-9_.]+$`. `npm run validate` accepts `content/briefings/1979_q3_stagflation.json` and rejects a briefing missing a scenario branch or a required forecast field.
- **SPEC-BRIEF-2** `[testable]` Briefing forecast quality scales with organizational investment: a pure `computeForecastNoiseScale(investment, params)` maps investment level to noise scale monotonically — higher investment yields lower noise (tighter forecasts); the floor `min_noise_scale` is always finite (no NaN at zero investment). A pure `applyForecastQuality(briefing, investment, params, rng)` returns a new `Briefing` with each scenario's forecast fields perturbed by uniform noise ±noiseScale; `unemployment_outlook` stays clamped to [0, 1]; `rng` is the caller's seeded generator (SPEC-SIM-1 — never `Math.random`). Params (`base_noise_scale`, `quality_slope`, `min_noise_scale`) live in `content/engine/forecast-quality.json` (schema-governed). The `investment` parameter is abstract (decoupled from the tech tree) so this SPEC does not block on the org/resource system.

## Confirmation hearing
- **SPEC-HEAR-1** `[testable]` A confirmation-hearing game start: the incoming Chair answers a congressional committee's questions, and the answers deterministically select the starting scenario and shape the starting institutional posture. The mechanism is schema-governed (`schemas/hearing.schema.json`) and content-driven (`content/hearings/`). A pure `resolveHearing(answers, hearing): { scenarioId, modifiers }` scores each scenario additively from the chosen answers' `scenario_weights`; the scenario with the highest total score is selected (alphabetical tiebreak). `state_modifiers` from all chosen answers are accumulated. Committee members posing questions use generated, non-historical names. Works with the 1979 scenario and gains variety once multi-scenario content is available.

## Mandate evaluator
- **SPEC-MANDATE-1** `[testable]` A pure `onTarget(state, params): boolean` in `src/engine/mandate.ts` checks whether the economy satisfies the central bank's mandate. For `mandate_type === "single"`: returns true iff `|inflation - target_inflation| <= tolerance_band`. For `mandate_type === "dual"`: also requires `|unemployment - unemployment_target| <= unemployment_band`. Params (`target_inflation`, `tolerance_band`, `mandate_type`, `unemployment_target`, `unemployment_band`) live in `content/engine/mandate.json` (schema-governed). `onTarget` is called inside `Session.proposeRate()` to supply the `onTarget` field to `applyMeetingOutcome`, wiring the third SPEC-CRED-1 credibility lever.

## Doctrine

- **SPEC-DOCT-1** `[testable]` A doctrine-adoption mechanic: a doctrine is content-defined (schema + `content/doctrines/`) with declared standing effects (additive modifiers to state vars) and a flip-flop cost. `adoptDoctrine(state, doctrine): GameState` records the doctrine in `state.flags` and applies its standing effects; no credibility cost on first adoption. `abandonDoctrine(state, doctrine): GameState` reverses the standing effects and deducts `flip_flop_cost` from credibility (clamped to [0, 100]). `adoptDoctrine` throws `DoctrineAlreadyAdoptedError`; `abandonDoctrine` throws `DoctrineNotAdoptedError` if preconditions are not met. At least one example doctrine in `content/doctrines/`; `npm run validate` green.
